# スマホ用ヘッダー

## 変更と受け入れ条件

760px以下では、ロゴ・テーマ切り替え・言語切り替えとハンバーガーボタンを1段に配置する。Projects / Notes / Aboutはボタンから開くメニューにまとめる。

- ページ上部ではヘッダーを表示する。72pxを越えて下へスクロールすると隠れ、上方向へ合計10px戻すと表示する。方向転換ごとに移動量をリセットし、微小な揺れやページ端のオーバースクロールで点滅させない。
- メニュー表示中はヘッダーを隠さない。ボタン、Escape、外側クリック、ヘッダー外へのフォーカス移動、リンク選択で閉じる。Escapeではボタンへフォーカスを戻す。
- 通常のナビゲーションとしてTabで操作でき、閉じた項目にフォーカスが入らない。キーボードフォーカス中のヘッダーを画面外へ隠さない。
- 日本語・英語、ライト・ダーク、320px幅、低い横向き画面に対応する。動きを減らす設定ではヘッダーの移動アニメーションを省く。
- 761px以上では従来のリンク・配置・通常スクロールを維持する。スマホで開いたメニューをPC幅で残さない。
- 変更をPRで確認できる状態にする。マージと本番デプロイはユーザーがPRを確認した後の工程とする。

## 検証結果

基準: `b106b4d`（ダークモード導入済みのmain）。既存の未追跡ファイルは対象外。

| 検証 | 結果 |
| --- | --- |
| PC配置の比較（761 / 900 / 1280px） | ロゴ・ナビゲーション・リンク・操作欄の位置、寸法、フォント、色、間隔が基準と一致 |
| PCの下・上スクロール | `position: static`を維持。900px下でtop=-900px、27px上へ戻してtop=-873px。ハンバーガーは非表示 |
| スマホの下・上スクロール（390px） | scrollY=1202でtop=-72px、25px上へ戻してscrollY=1177でtop=0px |
| スクロール途中のメニュー | 開いている間もtop=0pxで表示 |
| 開閉とフォーカス | Tabで最初のリンクへ移動。Escapeで閉じてボタンへ復帰。外側クリック、Tabでヘッダー外へ移動した場合も閉じる |
| ページ移動 | Aboutへ移動して閉じる。再度開くとAboutに`aria-current=page`が付く |
| レスポンシブ | 320px・英語・ライト表示で横にはみ出さない。PC幅へ変更後、320pxへ戻しても閉じている |
| 横向き（640×240px） | メニュー内をスクロールでき、Tabで最後のリンクに到達。リンク範囲178〜238pxで画面内に表示 |
| 実行時エラー | 検証ページのブラウザコンソールにerror / warnなし |
| 静的検証 | TypeScript・Lint成功 |
| ビルド | 本番ビルド成功、55ルートの事前描画、Journal公開防止検査成功 |
| 回帰テスト | Journal 36件、記事処理12件成功 |
| 日英・フォント | 8ルート×2言語、8,004件のグリフ・ウェイト比較成功 |

ブラウザ検証はCodex内蔵ブラウザで実施。実機Safari、OSの「動きを減らす」設定、印刷は未実行。動き軽減と印刷の条件はCSSで確認した。本番へのマージ・デプロイ・本番受け入れ確認は、このPRの確認後に実施する。

## 手元での確認

`npm run dev`で起動し、ブラウザ幅を390pxへ変更する。メニューを開閉した後、ページを下へスクロールし、少し上へ戻してヘッダーを確認する。開いたメニューからNotesやAboutへ移動する。320px・英語・ダークモードでも同じ操作を行い、最後に761px以上へ戻して従来のPCヘッダーになっていることを確認する。
