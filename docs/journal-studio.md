# Journal Studio：ブラウザーとローカルで記事を書く

2026-09-09。ローカルでのデザイン・操作確認を完了し、ユーザー承認を得てPRレビューと本番反映へ進める。

## 採用範囲

管理一覧・検索/タグ/種類/状態の絞り込み・並べ替え・一覧操作・削除/復元・公開設定・インポート改善（提案①〜⑥）と、メタデータ編集・原稿差し替え/履歴・ブラウザー執筆/自動保存（⑧〜⑩）。一括操作・予約公開・一括エクスポート（⑦⑪⑫）は含めない。

## 起動して確認する

`npm run journal:preview` を実行して `http://127.0.0.1:3003/journal/admin` を開く。ローカル専用D1と署名付きの確認用認証を使い、本番データには接続しない。既存ローカル記事は保持し、不足する列だけ追加する。変更後は停止して再起動すると再ビルドする。

- 「記事を書く」でIDを自動生成し、空の非公開下書きを作る。
- タイトル・要約・本文・タグ・種類・言語を編集。入力が止まって約1.5秒後に自動保存する。タグは入力欄を離れると確定する。
- 「公開設定へ」で保存済み下書きのプレビューを確認し、全体公開・限定公開・非公開を選ぶ。公開にはタイトル・要約・本文が必要。
- 公開後も編集できる。保存するだけでは読者が見る公開版は変わらない。「変更を反映する」で公開版を更新する。
- 変更履歴では保存済みの版を比較し、過去の版を下書きに戻せる。公開版はそのまま。変更箇所を含むブロックを色分けする。
- 競合や通信失敗では自動保存を停止して原稿を画面に保持する。再試行・Markdownダウンロード・保存版の読み直しを選べる。

一覧は削除用の44pxアイコンボタンと3点メニューを表示する。プレビュー・編集・Markdown保存・公開設定・復元はメニュー内。削除とメニューのボタンはホバーとキーボードフォーカスで操作名を表示する。メニューはEscapeまたはフォーカスが外れると閉じる。

## ローカルで作成する

```sh
npm run journal:new -- --title "記事のタイトル"
npm run journal:new -- --title "記事のタイトル" --dir /path/to/private-journal
npm run journal:new -- --template /path/to/custom-template.md --dir /path/to/private-journal
```

既定のテンプレートは `templates/journal.md`。IDと日本時間の日付を自動生成して、`<id>.md` を作る。IDはUUIDを用い、クラウドでも同じ形式で自動生成する。既存ファイルは上書きしない。既定の保存先はGit除外済みの `.journal-private/`。`JOURNAL_DIRECTORY` または `--dir` でリポジトリ外の原稿置き場を指定できる。ファイル権限は本人のみの読み書き。

記事IDはタイトルやファイル名を変えても維持する。ブラウザーで作った記事も「Markdownを保存」で取り出せる。ローカルで修正した後は、インポートまたは記事の「Markdownで差し替え」で同じ記事の下書きへ取り込む。同じIDがあれば保存版と比較し、明示操作で取り込む。IDのない新規ファイルはインポートの確認時に自動生成する。

自動同期・監視・CLIからの自動公開は行わない。既存の `journal:send` は認証付きの新規取り込み・同一原稿再送の互換経路として維持し、競合する原稿の強制上書きは行わない。

## 削除

- 公開停止：原稿を残して非公開にする。
- ゴミ箱：通常一覧から除外し、公開URLと共有リンクを停止する。
- 復元：必ず非公開。過去の共有リンクは復活しない。
- 完全削除：ゴミ箱内の対象記事を確認し、保存原稿・変更履歴・公開/共有設定を削除する。ローカルファイルや外部参照画像、別途取得済みのバックアップは消さない。

自動でゴミ箱を空にしない。操作はすべて管理者認証・同一Origin・version競合検査を通す。

## 保存方式と公開境界

既存IDとURLは変更しない。保存原稿はrevisionとして追記し、下書きの参照だけ更新する。公開中の参照は公開操作まで保持する。メタデータも下書きと一緒に反映する。以前のタグ専用APIの既存動作は互換性のため維持する。

プレビューは認証済みAPIで公開記事と同じMarkdown処理・サニタイズ・数式処理を使う。外部画像を読み込まず、リンクは無効化する。Mermaidはクライアント側で描画する。原稿はビルド入力や公開バンドルへ含めない。

履歴一覧は50件ずつ取得。管理一覧は検索条件をURLに保持し、50件ずつ取得する。保存日時順は同時刻にIDで順序を固定する。APIは受信サイズを制限し、SQLはパラメーター化する。
