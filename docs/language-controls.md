# 日英のボタン寸法とスマホの印刷操作

## 変更内容

- 共通ヘッダーの言語切り替えを `JP / EN`、44×44pxに統一。読み上げ名には切り替え先の説明を残す。
- ボタン型リンクは日英両方のラベルをグリッドの同じ位置に重ね、長い方の幅を確保する。現在の言語だけを表示・読み上げ対象とする。
- 適用先はAboutの印刷、ホームの職務経歴書、プロジェクト詳細の起動・他プロジェクト、記事のQiita・一覧、NotesのQiitaプロフィール。
- 画面幅760px以下の印刷操作は小さな「印刷 / Print」ボタンに集約。開くと直下にA4縦・A4横の選択肢が現れ、選ぶと直接印刷ダイアログへ進む。操作対象は高さ44px以上。外側のクリック、Escape、フォーカスが外へ移る操作でも閉じる。Escape・選択後はトリガーにフォーカスを戻す。
- PCでは既存の縦横2ボタンを維持。印刷メニューは印刷物に表示しない。
- Architecture Diagnosticの「アプリを開く」を `https://architect.morimizu.dev/` に更新。

## 検証

日英ボタンの寸法はHome、Notes、記事、About、設計診断とLissueの詳細の6ページを1118 / 390 / 320pxで実測。対象ボタンの幅・高さは日英で一致し、内部のはみ出しなし。Enterでの言語切り替えと非表示ラベルの読み上げ除外も確認。

印刷操作の回帰テストは `scripts/verify-print-controls.mjs`。320 / 390 / 760 / 761 / 1118px・日英で、開閉、キーボード、外側クリック、縦横の印刷指定、画面内への収まり、印刷時の非表示、アプリURLを確認する。OS印刷ダイアログは自動テスト中だけ置き換えて呼び出し回数を検証するため、実際のOSダイアログ操作は対象外。

Lint・TypeScript・本番ビルドと既存ナビゲーション回帰テストを実施。ライト・ダークのメニュー表示も目視確認。PRレビューで見つかった既存SSRテストの旧ボタン数前提を修正し、`node dev-pages/workshop/verify-render.mjs` でPC用2ボタン・閉じたスマホトリガー・非表示の2選択肢を個別に確認。

別件：設計診断の英語ページは320pxで既存の構成説明グリッドが約3px右へはみ出す。原因はグリッド内の英文の最小幅で、今回その箇所は変更していない。
